4.4 Couches de contrle et d'adaptation: dtail

Nous avons vu que certains call-backs de ControlLayer appelaient leur tour des mthodes de FileList. C'est notamment le cas de la mthode controlLayer.sendAction() qui appelle la mthode fileList.sendItem(), dclenchant l'envoi sur le rseau d'une page Html. 

public class ControlLayer implements Runnable {
  public FileList fileList;
  // Implements the call-back of the SenderGUI's sendButton
  public void sendAction () {
    fileList.sendItem ();
  }
}

public class FileList extends List {
  public void sendItem () {
    int fileListIndex = getSelectedIndex ();
    send (fileListIndex);
  }

  public int send (int i) {
    AMPThreadCarrier ampThreadCarrier = new AMPThreadCarrier (dbg);
    // Kill all previously running AMP process (stop the previous transmission)
    Executer.exec (AMPKillerCmd, dbg);
    // Create the Unix tar file to store all the inlined files contained
    // by the Html page
    String tarFilename = tarBuilder (directory, filename);
    // Send the Html page alltogether with its inlined files (images, etc.)
    ampThreadCarrier.cmdExec = "AMP " + filename;
    ampThreadCarrier.start ();
    return displayTime;
  }
}

Comme on le voit ci-dessus, la mthode sendItem() appelle son tour la mthode send(), cette dernire implmentant effectivement l'envoi de la page Html sur le rseau. Pour cela, plusieurs tapes sont ncessaires, le but tant de regrouper dans un seul fichier .tar Unix le fichier .html lui-mme, ainsi que tous les fichiers inclus (images, sons, films et autres appelettes).

Le programme tar Unix respecte la hirarchie des rpertoires, et le rcepteur pourra donc retrouver la mme structure que celle de l'metteur. Cependant, comme le fichier .tar est stock sur le rpertoire /tmp, tous les noms de fichiers inclus commençant par ../ (chemin relatif du rpertoire parent) ne pourront tre incorpors tel quels dans le .tar. Il faut donc trouver leur rpertoire, et les copier, au sein de /tmp, dans un autre rpertoire (intitul subDir dans notre cas). Dans le .html que reçoit le rcepteur, il faut donc que les noms de fichiers inclus correspondants soient modifis pour commencer par quelque chose comme /tmp/subDir.

Arrt de l'ventuelle transmission en cours:
on invoque pour cela un script Unix (killer), crit pour l'occasion (voir Annexe B), qui tue le processus Unix rpondant au nom d'AMP. Cette mthode est brutale, mais l'interface d'AMP ne permet pas d'tre plus fin.
Extraction des noms des fichiers inclus:
on utilise une mthode de la classe Adapter, qui extrait les noms de fichiers inclus dans le .html original, et rcrit un autre .html avec les ventuels nouveaux noms (ceux commençant par /tmp/subDir).
Excution de la commande Unix tar:
cette commande regroupe sous un mme fichier tous les fichiers ncessaires l'interprtation de la page Html.
Compression du fichier .tar:
on utilise la commande Unix gzip.
Nettoyage:
il faut effacer tous les sous-rpertoires et fichiers qui ont servi la construction du .tar.

Enfin, aprs avoir cr le .tar, il faut envoyer ce fichier sur le rseau en utilisant le protocole AMP. Or, l'appel au serveur AMP est bloquant, et l'on veut pouvoir stopper la transmission tout moment: bref, l'on veut garder la main pendant la transmission. Aussi, il est ncessaire de lancer un Thread, qui va implmenter l'appel au serveur AMP.

Pour des raisons de clart, ce Thread est implment dans la classe AMPThreadCarrier, ce qui prsente l'avantage de fournir des moyens de communication entre le Thread et le processus appelant (par l'intermdiaire d'attributs static). Cela permet par exemple de faire excuter plusieurs fois le serveur AMP sur des noms de fichier diffrents, sans dtruire le Thread, mais simplement en le stoppant. Ici, donc, l'AMPThreadCarrier lance sous forme de commande Unix le serveur AMP. Pour stopper le Thread, il faudra tuer le processus AMP, ce qui permettra AMPThreadCarrier de finir sa tche.

Pour finir, il est noter que c'est la mthode send() de FileList qui lance AMPThreadCarrier: chaque fois que l'on demandera d'envoyer un fichier sur le rseau, la mthode run() d'AMPThreadCarrier sera invoque avec le nom de fichier transmettre correspondant. AMPThreadCarrier est diffrent du Thread lanc par ControlLayer pour grer le mode automatique. Dans le mode automatique, la mthode fileList.send() est invoque sur chacun des fichiers transmettre, et cette dernire lance son tour un AMPThreadCarrier. Le mode automatique est gr sous forme de Thread afin de pouvoir garder la main et, notamment, stopper ce mode.
